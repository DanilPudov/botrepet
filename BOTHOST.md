# Выкладка на BotHost (bothost.ru)

## Что заполнять в форме создания бота

| Поле формы | Что указать |
|---|---|
| **Язык разработки** | **Python** |
| **Версия языка** | **3.11** (рекомендация BotHost; наш код проверен на совместимость с 3.11) |
| **Git URL репозитория** | ссылка на **ваш** GitHub-репозиторий, например `https://github.com/ВАШ_ЛОГИН/repetitor-bot.git` |
| **Ветка** | `main` |
| **Описание** | `Telegram-бот для репетиторов` (любое) |
| **Дополнительные настройки** | **не трогать** |
| **Использовать домен** | **НЕТ** — бот работает через long polling, входящий порт не нужен |
| **Главный файл (точка входа)** | `bot.py` |
| **Собственный Dockerfile** | **НЕТ** (BotHost сгенерирует сам из `requirements.txt`). Если сборка не пройдёт — включить и использовать наш `Dockerfile` |

## Переменные окружения (ключ = значение)

| Ключ | Значение | Обязательно |
|---|---|---|
| `BOT_TOKEN` | ваш токен от @BotFather (`9090633923:...`) | **Да** |
| `DATA_DIR` | `/app/data` | **Да** (постоянное хранилище: state.json, логи, заметки) |
| `TZ` | `Europe/Moscow` | Желательно (бот ставит сам, но пусть будет) |
| `PYTHONUNBUFFERED` | `1` | Желательно (логи в реальном времени) |

`TELEGRAM_BOT_TOKEN` — необязательно, если указан `BOT_TOKEN`.

## Что загрузить в репозиторий GitHub

Всё содержимое папки `bot-git` (архив `bot-git.zip`):
- `bot.py` + все модули (`checks_writer.py`, `students.py`, `schedule.py`,
  `sheets_util.py`, `links.py`, `notes.py`, `suggestions.py`, `reviews.py`,
  `referrals.py`, `reconcile.py`, `statuses.py`, `pdf_parser.py`, `check_setup.py`);
- `requirements.txt` — зависимости;
- `config.json` — **без токена** (токен в переменной `BOT_TOKEN`);
- `bothost.json` — точка входа и версия Python;
- `.gitignore` — чтобы секреты не попали в репозиторий.

Создать репозиторий: GitHub → New repository → имя `repetitor-bot` → **Public**
→ Create. Затем «uploading an existing file» → перетащить файлы → Commit.

## Что загрузить в папку /app/data (файловый менеджер в панели бота)

Эти файлы — **секреты и состояние**, в Git их нельзя:

1. **`service_account.json`** — ключ Google сервисного аккаунта
   (сейчас лежит в `D:\Репетиторство DSH\dsh1-514118-024de3bf93f9.json`).
   Скопировать и переименовать в `service_account.json`.
2. **`state.json`** — с текущего компьютера (`D:\Репетиторство DSH\bot\state.json`).
   Без него все репетиторы потеряют доступ и придётся добавлять заново.

## Порядок действий

1. Создать репозиторий GitHub, загрузить туда файлы из `bot-git.zip`.
2. В BotHost: **Добавить бота** → заполнить форму по таблице выше.
3. Указать переменные окружения (`BOT_TOKEN`, `DATA_DIR`, `TZ`).
4. Нажать «Создать/Задеплоить», дождаться сборки, проверить логи.
5. Открыть панель бота → **файловый менеджер** → папка `/app/data` →
   загрузить `service_account.json` и `state.json`.
6. Перезапустить бота (кнопка Restart в панели).
7. В Telegram написать боту `/start` — должен ответить.

## Почему бот не стартует — частые причины

| В логах | Причина |
|---|---|
| `В config.json не заполнен "telegram_token"` | не задана переменная `BOT_TOKEN` |
| `FileNotFoundError: service_account.json` | ключ Google не загружен в `/app/data` |
| `Killed` / код 137 | мало RAM (256 МБ на бесплатном тарифе) — нужен тариф 99 ₽ |
| `Conflict: terminated by other getUpdates` | бот уже где-то запущен (на компьютере) — остановить локальный |
| `ModuleNotFoundError` | не подтянулся `requirements.txt` |

## Как обновлять бота дальше

**Вариант A (Git, удобнее):** изменить файлы в репозитории → BotHost
подхватит при новом деплое (на платном тарифе — автоматически при push).
Данные в `/app/data` и `config.json` в `DATA_DIR` сохраняются.

**Вариант B (архив):** загрузить новый `.zip` через кнопку «залить новый архив».

Я (ассистент) **не имею доступа** к вашему аккаунту BotHost и GitHub,
поэтому кнопки нажимать нужно вам. Но я готовлю за вас:
- готовый архив с обновлённым кодом;
- точные значения всех полей и переменных;
- тексты коммитов.

## Важно про тариф

- **Бесплатный (256 МБ)** — риск: бот потребляет 120–250 МБ, возможен OOM-kill.
- **99 ₽ (1 ГБ)** — рекомендуется. Также только на платных тарифах доступна
  загрузка из архива и переменные окружения.


## Ошибка «Бот уже запущен (pid 1)» и «Conflict: terminated by other getUpdates»

**Причина:** защита от второго экземпляра проверяла `os.kill(pid, 0)`.
Внутри Docker бот работает как **PID 1**, а файл `bot.lock` лежит в `/app/data`
и сохраняется между перезапусками. Поэтому новая копия видела «живой pid 1»
и завершалась — контейнер уходил в цикл перезапусков («подключено/отключено»).

**Исправлено:** блокировка теперь через `flock` — она снимается автоматически,
когда процесс умирает. Файл `bot.py` нужно обновить в GitHub.

### Как обновить один файл на GitHub

1. Открыть `bot.py` в вашем репозитории.
2. Нажать значок **карандаша** (Edit) или «...» → Delete + Upload.
   Проще: **Add file → Upload files** → перетащить новый `bot.py` → Commit
   (GitHub заменит файл).
3. В BotHost нажать **пересобрать/обновить** (не просто Restart).

### Обязательно проверьте переменные окружения

В настройках бота BotHost должны быть:

| Ключ | Значение |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `DATA_DIR` | `/app/data` |

Без `BOT_TOKEN` бот выйдет с сообщением «В config.json не заполнен telegram_token».

### Файлы в /app/data (файловый менеджер)

- `service_account.json` — ключ Google;
- `state.json` — список репетиторов с вашего компьютера.

Без `service_account.json` бот запустится, но при первом обращении к таблицам
будет ошибка `FileNotFoundError`.
